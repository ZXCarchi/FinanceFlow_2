# FinanceFlow JSON API

All endpoints are same-origin under `/api/`. Authentication uses Django's HttpOnly session cookie. Send `Content-Type: application/json` and `X-CSRFToken` on every mutation. Obtain `csrfToken` from session, login or register responses; login rotates it. Fetch with `credentials: 'same-origin'`. No CSRF exemptions.

Money values are **decimal strings** (`"1250.50"`), never binary floats. Foreign keys use integer IDs named `wallet` / `category`. Dates are ISO `YYYY-MM-DD`, years 1900–9998. Optional category and target_date accept `null`. Errors are `{ok:false,error:"...",errors:{field:["message"]}}`, with HTTP 400 (invalid), 401 (authentication), 404 (not found), 409 (conflict), 429 (rate limit). The `errors` object can be omitted. Successful CRUD mutations return `{ok:true,item:{...}}`; deletion returns `{ok:true}`. Refresh state after mutations.

## Authentication

- `GET /api/session` → `{authenticated:boolean,user:{id,email,first_name}|null,csrfToken:string}`.
- `POST /api/register` body `{email,first_name,password,password_confirm?,currency?:"PLN"}` → `{ok:true,user,csrfToken}`. Creates a zero-balance Main account and starter categories. Strong password required.
- `POST /api/login` body `{email,password}` → `{ok:true,user,csrfToken}`.
- `POST /api/logout` body `{}` → `{ok:true,csrfToken}`.

## State

`GET /api/state?month=2026-10` (default current month) returns:

```
{
  month: "2026-10",
  user: {id,email,first_name},
  profile: {currency:"PLN",expected_monthly_income:"0.00"},
  wallets: [{id,name,wallet_type:"card",opening_balance:"0.00",balance:"0.00",is_active:true}],
  categories: [{id,name,code,kind:"expense",icon,color}],
  transactions: [{id,kind:"expense",title,amount:"0.00",wallet:1,category:1,date:"2026-10-09",note:""}],
  goals: [{id,name,target_amount:"1000.00",saved_amount:"0.00",target_date:null,icon,progress:0,remaining:"1000.00"}],
  budgets: [{id,category:1,monthly_limit:"100.00",spent:"0.00",remaining:"100.00",percent:0}],
  recurring: [{id,title,amount:"10.00",kind:"expense",wallet:1,category:null,day_of_month:1,is_active:true}],
  summary: {income:"0.00",expenses:"0.00",balance:"0.00",net:"0.00",savings_rate:0},
  trend: [{month:"2026-05",label:"May",income:"0.00",expense:"0.00"}, ... six months ending in selected month],
  category_spending: [{category:1,name:"Food",icon:"🍜",color:"#ff9f43",amount:"0.00",percent:0}],
  plan: {
    essential_pct:"50.00",lifestyle_pct:"30.00",savings_pct:"20.00",planning_income:"0.00",
    essential_amount:"0.00",lifestyle_amount:"0.00",savings_amount:"0.00",
    income:"0.00",expenses:"0.00",balance:"0.00",avg_daily:"0.00",projected_expenses:"0.00",
    projected_balance:"0.00",remaining_expected_income:"0.00",category_targets:[],alerts:[]
  }
}
```

Transactions, summary income/expenses/net/savings_rate, category spending and budget consumption follow the selected month. Balance is the current total of active wallets through today, not monthly net. Savings progress is manual (updating a goal does not create a transaction). Currency is a display denomination; no exchange-rate conversion occurs. Future-dated transactions appear in their selected month, but affect current wallet balances only on their entered date. Plan uses the greater of expected and selected-month actual income and stays zero when neither exists. Plan amounts add exactly to planning income, using largest fractional remainders to distribute cents without negative allocations. Projections use active accounts, their month-opening balances and their elapsed actual spending; archived accounts remain in historical reports but are excluded from balance projections.

## CRUD

Collections: `wallets`, `categories`, `transactions`, `goals`, `budgets`, `recurring`.

- `POST /api/{collection}` creates.
- `PATCH /api/{collection}/{id}` updates supplied fields only.
- `DELETE /api/{collection}/{id}` deletes. A wallet with transactions or recurring items cannot be deleted; set `is_active:false` to archive it. A category used by any transaction, recurring item or budget cannot be deleted.
- Optional trailing slash accepted on all API endpoints.

Writable fields:

| Collection | Fields |
| --- | --- |
| wallets | name, wallet_type (`card/cash/savings/other`), opening_balance (negative allowed), is_active |
| categories | name, kind (`expense/income/both`), icon, color (`#RRGGBB`); code generated by backend |
| transactions | kind (`income/expense`), title, amount (>0), wallet (owned active wallet ID), category (owned ID or null matching kind), date, note |
| goals | name, target_amount (>0), saved_amount (>=0), target_date (date or null), icon |
| budgets | category (owned expense/both ID), monthly_limit (>0); one per category |
| recurring | title, amount (>0), kind, wallet, category, day_of_month (1–31), is_active |

Decimals allow at most two places. Non-finite values, unknown fields and wrong JSON types are rejected. Overfunded goals are allowed; progress is capped at 100 and remaining at 0. Budget percent can exceed 100 so overspending remains visible. No object can reference another user's data.

## Other endpoints

- `PATCH /api/settings` body `{first_name?,currency?,expected_monthly_income?}`. Currency is PLN/EUR/USD/GBP/KGS; expected income >=0. Returns `{ok:true,profile,user}`.
- `PATCH /api/plan` body `{essential_pct,lifestyle_pct,savings_pct}` (partial updates allowed). Values 0–100, max two decimal places, must total **exactly 100** after merging. Returns `{ok:true,plan}`. Applied plan is manual and saved per account.
- `POST /api/recurring/apply` body `{month?:"YYYY-MM"}` → `{ok:true,created:number}`. Applies active schedules due on/before today in the selected month. Future months rejected. Day 29–31 clamps to month end. A database-backed occurrence record prevents duplicate application even after editing/deleting generated transactions.
- `GET /api/export?month=YYYY-MM` downloads UTF-8 CSV for selected month (default current). Formula-like text is neutralized.

- `POST /api/coach` body `{message:string}` → `{reply:string}`. A local rule-based helper using account data; it does not contact AI services.
