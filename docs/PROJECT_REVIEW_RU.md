# FinanceFlow: разбор и переделка

## Что было в исходнике

Архив уже содержал Python/Django. Страницы собирались Django-шаблонами, JavaScript отвечал за небольшие интерактивные элементы, базой была SQLite. Поэтому сохраняем работающие модели и серверный каркас и заменяем интерфейс на самостоятельное JavaScript-приложение.

Главные найденные проблемы:

- Пользователь не мог задавать собственные доли бюджета: они выбирались алгоритмом.
- Для большинства сущностей отсутствовали полноценные изменение и удаление.
- Не везде строго проверялись положительные, конечные суммы и допустимые значения.
- Повторное создание регулярных платежей защищалось сравнением названия и суммы, что не исключало гонки.
- Настройки по умолчанию включали DEBUG и известный резервный секрет.
- Старый обработчик мог перенаправлять на произвольный адрес из формы; CSV не нейтрализовал формулы.
- Балансы учитывали будущие операции как уже произошедшие.

## Что меняем

1. **JavaScript + Python + PostgreSQL.** Django остаётся сервером и отдаёт JSON API. JavaScript рисует интерфейс, формы и диаграммы. PostgreSQL является основной базой, есть Docker Compose для запуска.
2. **Одна система дизайна.** Общие цвета, сетка, типографика, поля, кнопки, карточки, окна и навигация. Основной язык — английский, по вашему выбору.
3. **Пользователь управляет числами.** Доход, начальные балансы, операции, накопления, цели, лимиты и три доли бюджета редактируются. Доли обязаны суммироваться до 100%; распределение копеек сохраняет общую сумму.
4. **Диаграммы из данных.** Фактические расходы считаются по операциям за выбранный месяц, план — по доходу и указанным процентам. Изменения сохраняются на сервере и перечитываются после сохранения.
5. **Безопасность.** Сессии Django, CSRF, защита от выполнения сторонних скриптов, проверка принадлежности каждой записи, ограничения входа, ограничения базы и безопасный CSV. Это базовая защита; полноценный внешний аудит публичного развёртывания сюда не входит.
6. **Адаптивность и движение.** Общие стили для ноутбука, планшета и телефона, короткие переходы интерфейса с учётом настройки уменьшения анимации.

## Figma и анимации

Все четыре части не нужно объединять в одну технологию: JavaScript, Python и PostgreSQL работают в приложении, Figma служит для проектирования интерфейса. В Figma можно создать компоненты, варианты состояний и интерактивный прототип с [Smart Animate](https://help.figma.com/hc/en-us/articles/360039818874-Smart-animate-layers-between-frames). В работающем сайте переходы реализуются CSS и JavaScript.

Figma-файл не создан: Figma не подключена, ссылки на макет нет. Для этой переделки компоненты и анимации реализованы непосредственно в коде, поэтому отдельный макет не блокирует работу. Для дальнейшей передачи дизайнеру удобно перенести цвета, размеры, кнопки, поля и состояния страниц в Figma.

## Что стоит делать дальше

- Перед публичным запуском: PostgreSQL на хостинге, HTTPS, резервное копирование с проверкой восстановления, мониторинг ошибок.
- Следующий продуктовый этап: восстановление пароля через почту, подтверждение адреса, перевод между счетами как связанная операция, импорт выписок с предварительным просмотром.
- При большом числе операций: серверная пагинация и агрегаты вместо полной загрузки месячного списка.
- Если понадобятся несколько валют одновременно: отдельная валюта каждого счёта, источник курсов и явная дата конвертации.

Пока не нужны платные AI-сервисы, подключение банков и тяжёлые анимационные библиотеки: они усложнят запуск без решения главной задачи учёта. Текущий помощник использует локальные правила и реальные записи пользователя.

## Важные границы

Смена валюты не конвертирует старые суммы. Цели — ручной учёт прогресса, без автоматического перевода денег. Регулярные операции добавляются по кнопке, фонового расписания нет. Проценты планирования не изменяют фактические доходы и расходы. Существующая удалённая база не переносилась, сайт не публиковался, GitHub-репозиторий не изменялся.

Настройки публичного запуска сверены с [официальным руководством Django](https://docs.djangoproject.com/en/5.2/howto/deployment/checklist/). Итоги фактических проверок находятся в `VERIFICATION.md`.
